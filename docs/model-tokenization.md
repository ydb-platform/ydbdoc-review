# F05: размер запроса

Перед разбиением `protect` заменяет атомы маркерами. `chunk_document` сначала
проверяет целый защищённый файл. При необходимости выбирает границы предложений
и блоков из парсера; каждый выбранный чанк проверяется целиком, вместе с промптом
(в том числе переданным содержимым глоссария) и полным резервом ответа.
Нет фиксированного числа частей, коэффициента символов/токен или байт/токен.
Двоичный поиск сокращает число проверок; при отсутствии найденной границы
проверяются остальные, поскольку токенизация не обязана быть монотонной.
Он не обещает математически минимальное число чанков.

`RequestBudget.count_output_tokens` отдельно считает сырой ожидаемый ответ:
вычитание максимумов chat-overhead разных моделей могло занизить оценку.
В переводе, критике и исправлении `budget.for_choice(choice)` использует
максимум только по primary/alternative моделям данного обращения. Оператор задаёт context/output лимиты, допустимые для каждой из них.
Длина исходника — лишь оценка объёма перевода: расширение при переводе возможно,
поэтому `finish_reason=length` по-прежнему означает незавершённый результат.

Для стандартного Yandex Cloud endpoint и явно разрешённых версий
`yandexgpt-5-pro`, `yandexgpt-5.1`, `yandexgpt-5-lite` runtime лениво вызывает официальный
[TokenizeCompletion](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/Tokenizer/tokenizeCompletion)
с точным `gpt://folder/model` и всеми сообщениями, а для ответа —
[Tokenize](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/Tokenizer/tokenize).
Конструктор runtime не обращается к сети. Таймаут не более 30 секунд; нет
повторов, технических generation-fallback или подстановки другой модели при
ошибке токенизации. Ошибка даёт CapacityError до генерации. Кэш хранит только
хеш запроса и целое число на время запуска; не дублирует тексты в контексте.
Повторная проверка идентичного запроса не вызывает HTTP повторно.

По [официальному описанию](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/tokens)
каждая модель имеет собственный токенизатор, методы Tokenizer описаны для моделей
Яндекса. DeepSeek и неизвестные версии отклоняются явно до любого HTTP, даже если
неподдерживаемая модель настроена только как альтернатива. Проверяется весь
выбранный набор моделей, включая подсчёт пустого ответа. Defaults не изменены:
выбранный `deepseek-v32` не имеет подтверждённого Tokenizer и останавливает расчёт
с CapacityError. Это ограничение требует согласования модели, а не скрытой замены.
Общий URL провайдера не доказывает совместимость конкретной модели. Согласно
[тарифам](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing), Tokenizer не
тарифицируется; это токенизация, а не генерация. Источники проверены 2026-09-18;
живые обращения с текстами или генерация при разработке не выполнялись.

Для другого deployment или локального проверенного токенизатора предусмотрен
явный Python adapter `load_runtime(..., token_counter=adapter)`: callable
считает полные сообщения, `adapter.count_output(text)` — сырой ответ. Привязка
адаптера к моделям и допустимые лимиты — обязанность интеграции. Через JSON
исполняемый код не загружается; неподтверждённого default tokenizer нет.
