# F05: размер запроса

Перед разбиением `protect` заменяет атомы маркерами. `chunk_document` сначала
проверяет целый защищённый файл. При необходимости выбирает границы предложений
и блоков из парсера; каждый выбранный чанк проверяется целиком, вместе с промптом
(в том числе переданным содержимым глоссария) и полным резервом ответа.
Нет фиксированного числа частей, коэффициента символов/токен или байт/токен.
Двоичный поиск сокращает число проверок; при отсутствии найденной границы
проверяются остальные, поскольку токенизация не обязана быть монотонной.
Он не обещает математически минимальное число чанков.

`RequestBudget.count_output_tokens` отдельно считает сырой ожидаемый ответ:
вычитание максимумов chat-overhead разных моделей могло занизить оценку.
В переводе, критике и исправлении `budget.for_choice(choice)` использует
максимум только по primary/alternative моделям данного обращения. Оператор задаёт context/output лимиты, допустимые для каждой из них.
Длина исходника — лишь оценка объёма перевода: расширение при переводе возможно,
поэтому `finish_reason=length` по-прежнему означает незавершённый результат.

Для стандартного Yandex Cloud endpoint и явно разрешённых версий
`yandexgpt-5-pro`, `yandexgpt-5.1`, `yandexgpt-5-lite` runtime лениво вызывает официальный
[TokenizeCompletion](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/Tokenizer/tokenizeCompletion)
с точным `gpt://folder/model` и всеми сообщениями, а для ответа —
[Tokenize](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/Tokenizer/tokenize).
Конструктор runtime не обращается к сети. Таймаут не более 30 секунд; нет
повторов, технических generation-fallback или подстановки другой модели при
ошибке токенизации. Ошибка даёт CapacityError до генерации. Кэш хранит только
хеш запроса и целое число на время запуска; не дублирует тексты в контексте.
Повторная проверка идентичного запроса не вызывает HTTP повторно.

Для `deepseek-v4-flash` используется локальный официальный токенизатор
[deepseek-ai/DeepSeek-V4-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash/tree/60d8d70770c6776ff598c94bb586a859a38244f1),
revision `60d8d70770c6776ff598c94bb586a859a38244f1`. В пакет включены только
`tokenizer.json` (6 367 146 байт), `tokenizer_config.json` и MIT LICENSE;
веса и исполняемый код Hugging Face не загружаются. Runtime читает локальные
данные через `tokenizers==0.22.2`, проверяет SHA-256 файла перед загрузкой:
`8f9f37ca37fdc4f5fd36d5cf4d3b0e8392edb4e894fd10cc0d70b4957c8633cf`.
Отсутствие зависимости/файла, повреждение или несовпадение хеша дают CapacityError.
Сеть для этого подсчёта не нужна. Не используются токенизаторы V3.2, V4.1 или Pro.

Формат сообщения — ограниченная специализация официальных
[`render_message` / `encode_messages`](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash/blob/60d8d70770c6776ff598c94bb586a859a38244f1/encoding/encoding_dsv4.py):
SHA-256 reference script: `bdbd57c132a1b3725042323d02b98b9d1df28e5f388f134399555d041f5055e0`.
Поддерживаются один необязательный system и один user; полный текст содержит BOS, system,
User, user, Assistant и маркер режима. Все промпты и глоссарий считаются
в составе этих сообщений. Дополнительный BOS/EOS библиотекой не добавляется,
что соответствует `add_bos_token=false` / `add_eos_token=false` upstream config.
В режиме chat добавляется `</think>`, thinking — `<think>`. При unset
`reasoning_effort` считается максимум реальных токенизаций обоих форматов;
это не утверждение, что reasoning отключён. Явные `none` и `high` выбирают
соответствующий формат; прочие значения, роли, tools и мультимодальные данные
отклоняются. Сырой предполагаемый ответ считается без chat-обёртки.
Наличие энкодера для `none` не подтверждает поддержку этого API-параметра
на YC; выбор параметров провайдера описан отдельно в F04.

Основание привязки к YC — [каталог провайдера](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models)
называет именно DeepSeek V4 Flash с контекстом 1 048 576 токенов. Подсчёт
точен для закреплённого официального токенизатора и указанных форматов;
тождество внутреннего framing YC этому reference не измерялось живым вызовом.
В частности, скрытые инструкции или последующее обновление deployment могут
изменить входной usage. Это предел проверки, а не измеренная совместимость.
[Yandex Tokenizer](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/tokens)
описан как бесплатный для моделей Яндекса;
[Responses input_tokens](https://aistudio.yandex.ru/en/docs/ai-studio/api/Responses/Getinputtokencounts)
помечен CURRENTLY NOT SUPPORTED. Эти методы не вызываются для DeepSeek.
YC API-key/IAM/folder credentials в среде разработки отсутствовали; генерации
и токенизирующих запросов в YC не было. Источники и локальные артефакты
проверены 2026-09-19.

Альтернатива `yandexgpt-5-pro` по-прежнему считается своим YC Tokenizer.
Неизвестные provider/model и неподдержанные версии отклоняются до любого HTTP,
даже если они настроены только как альтернатива. Общий URL провайдера не
считается основанием подставить чужой токенизатор. Согласно
[тарифам](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing), Tokenizer не
тарифицируется; это токенизация, а не генерация.

Для другого deployment или локального проверенного токенизатора предусмотрен
явный Python adapter `load_runtime(..., token_counter=adapter)`: callable
считает полные сообщения, `adapter.count_output(text)` — сырой ответ. Привязка
адаптера к моделям и допустимые лимиты — обязанность интеграции. Через JSON
исполняемый код не загружается; неподтверждённого default tokenizer нет.
