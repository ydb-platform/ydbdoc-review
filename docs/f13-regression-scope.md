## Измерения и ограничения

`F13_MEASUREMENTS_DIR` задаёт каталог отдельных JSON. Измеряется wall time дочернего
CLI (без подготовки фикстуры и seed), число HTTP попыток модели, расход по
синтетическому тарифу, байты восстановленного контекста, сумма payload текущего
run в SQLite run_objects (включая manifest/поколения), число и время Git subprocess.
Git не кешируется mock-адаптером. JSON содержит проверяемую ревизию.

Это не live-проверка YDB, GitHub, провайдера или YFM; не SLA и не облачный счёт.
Контроль реального YFM обеспечивают существующие independent CLI тесты.

## Полученные результаты разработки

Полный existing CLI: 450 сценариев, 446 PASS / 4 FAIL за 718.17 s. Четыре
устаревших ожидания исправлены и адресно перепроверены: 4 PASS за 26.96 s.
Это полный исходный прогон плюс адресная проверка, не утверждение о новом полном
зелёном прогоне итогового SHA. Два независимых multifile F09 сценария: 2 PASS.

Проверка 21 зависимого пути сохраняет требования §2 и §6.1: короткий комментарий
содержит N/L, имя документа и действия; тест проходит по опубликованному URL через
receipt commit/tree/blob и проверяет все 21 пути в содержимом доступного артефакта,
включая путь сверх лимита. Запрет модели и translation PR сохранён. Эту трактовку
должен проверить независимый тестер. Security/cancellation проверки сохранены;
выявленные ранее дефекты исправлены принятым F11 followup.

Повторные чтения одного immutable target оказались измеренным ресурсным дефектом:
до оптимизации green/doc_verify делал 8217 cat-file за 32.913 s (CLI 37.140 s).
Теперь check_links хранит локальный FIFO кеш: до 128 значений, суммарно 1 MiB,
blob больше 64 KiB не кешируется. Ошибки I/O не кешируются; каждая ссылка и её
диагностика обрабатываются отдельно. Кеш не переходит между проверками или SHA.
После изменения: 23 cat-file за 0.102 s (CLI 3.943 s). Модельные вызовы, стоимость
и размер контекста в сопоставимых сценариях совпадают. Это локальное измерение,
не гарантия времени или числа вызовов для других деревьев.

Регрессия на старом коде: 2 FAIL (257 чтений вместо одного). После исправления
кеш, links/build и F08: 51 PASS за 10.79 s, включая новые SHA, SVG/include,
неизменность диагностик, лимиты количества/байтов и исключения чтения.

## CI и границы приёмки

Existing CLI и scale вместе дали бы 829.89 s по отдельным измерениям, слишком
близко к лимиту 900 s. Поэтому добавлена отдельная группа scale: все 15 сценариев,
те же размеры фикстур и ограничения. Остальные CLI тесты остаются в cli. Полная
коллекция назначается ровно один раз восьми группам; workflow matrix соответствует
GROUPS. Лимиты группы 900 s, теста 120 s и дочернего CLI 110 s не увеличены.

Доказательства лежат в workspace dispatch/translation-fix: f13-existing-cli-rerun.log,
f13-existing-cli-targeted-fix.log, f13-f09-boundary.log, f13-cache-before.log,
f13-cache-after.log, f13-scale-green.log, f13-scale-green-after-cache.log,
f13-scale-failed-build.log, f13-scale-faults.log, f13-developer-evidence.json,
f13-measurements/*.json. Частичный ранний baseline явно отделён в
f13-existing-cli-baseline-summary.json; он не считается полным прогоном.

Итоговый интегрированный SHA ещё требует независимой проверки всех CI групп и
package-команд: ruff check src tests scripts; uv build --no-sources; uv pip check;
locked export в сравнении с requirements.txt. Предыдущие принятые F03/F07
интеграционные тесты остаются частью CI. Полная F13 не объявлена принятой;
совместимость реальной модели и выбор замены остаются отдельным ограничением.

Локальные проверки выполняются с выделенным heavy-слотом, login:false,
PYTHONPATH=src, Node24/yfm5.61.0 в PATH, через tools/run_guarded.py --heavy
--timeout 900 и .venv-ci/bin/python -m pytest -vv. Без xdist/nohup; при UNHEALTHY
нужна диагностика своих процессов, обход guard запрещён.
