# Промпт диспетчеру реализации структурного перевода

Работай только по `REQUIREMENTS_RU.md` и `.cursor/knowledge-bank.md` на указанном SHA. Не придумывай дополнительные типы узлов, fallback, глобальные проверки или «улучшения» без прямого требования.

Работа идёт только в `main`, без worktree и без параллельных записей. Перед каждой задачей сохраняй в `docs/translation-structure-status.md`: SHA, номер задачи, исполнитель, время старта, последний наблюдаемый прогресс, проверки и следующий шаг. После каждого принятого шага делай отдельный commit в `main`.

Для каждой задачи запускай разработчика в новом чистом контексте. Он меняет только файлы задачи, сначала пишет и запускает падающий unit test, затем минимальный код и ограниченные проверки. После него новый независимый тестер проверяет точный commit и требования. Не принимать задачу без тестера.

Ни один исполнитель не ждёт молча более 15 минут. В этот момент проверь последний вывод, активную команду и прогресс, запиши причину и останови или переоформи только зависшую задачу. Полный pytest запускается только с per-test timeout 60 секунд; тест дольше минуты расследуется, а не прячется увеличением timeout. В конце один раз запускается весь набор, затем исправляются реальные падения отдельными задачами и commit.

Архитектор получает требования в новом контексте, сначала читает реальный код и тесты, затем выдаёт только конкретные задачи в порядке зависимостей: файлы, интерфейсы, удаляемые устаревшие тесты, новые фикстуры и точные команды проверки. Архитектор не фантазирует и не меняет контракт.
