# Разработка ydbdoc-review

Перед изменениями прочитайте [действующие требования](REQUIREMENTS_RU.md). Старые документы из Git-истории не добавляют требований. Существующие код, промпты и тесты могут отражать прежнее поведение; при реализации нового контракта их нужно согласовать с ним.

## Окружение и проверки

Python 3.11+, зависимости и настройки инструментов — в [pyproject.toml](pyproject.toml).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest
ruff check src tests
```

Для отдельного изменения сначала запускайте относящиеся к нему тесты. Перед завершением проверяйте затронутый процесс целиком. Обычные тесты используют имитацию модели; платные обращения не нужны. Исправление бага сопровождается воспроизводящим тестом. Требования к полноте тестирования находятся в разделе «Тестирование и приёмка» основного контракта.

## Изменения

- Работайте от актуального `main`, сохраняя чужие и локальные изменения.
- Описывайте конкретное изменение поведения и результаты проверок. Не выдавайте обновление документации за реализацию функционала.
- При изменении согласованного контракта обновляйте [требования](REQUIREMENTS_RU.md) и [краткий банк](.cursor/knowledge-bank.md) в одном коммите.
- Не добавляйте историю инцидентов, старые задания и дублирующие спецификации в действующую документацию.
- Не включайте секреты в коммиты и логи.

Точки входа текущей реализации: [CLI](src/ydbdoc_review/cli.py), [Action](action.yml), [entrypoint.sh](entrypoint.sh). Настройки выпуска образа находятся в [.github/workflows/docker-publish.yml](.github/workflows/docker-publish.yml). Публикация документации в `main` сама по себе не означает выпуск новой версии приложения.
